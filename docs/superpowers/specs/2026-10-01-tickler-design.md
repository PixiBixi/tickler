# Tickler V1 design

Date: 2026-10-01. Status: approved in conversation (sections 1 to 5), written up without a further review round at the owner's request.

## Goal

Replace the "Claude" list of Apple Reminders as the store for the reminders Claude Code writes for its user. Apple Reminders has no date filter worth the name, buries the resume command in plain text and gives no way to act on a reminder from its notification. Tickler is a macOS-only app plus a CLI:

- Claude writes and reads reminders through the `tickler` CLI (JSON output).
- The human gets a menu bar item, a window with date filters, notifications at the due time with actions (resume the Claude session, snooze, reschedule, done, open the ticket or Slack thread), and a one-way copy of every reminder in a calendar of their choice.

Success: the owner never copies a `claude --resume` command again, sees the day at a glance, and every reminder Claude writes ends up in their calendar.

## Out of scope for V1

- Recurring reminders.
- Repeated nagging: one notification per reminder, then it stays red.
- Phone access (Mac only; the calendar copy covers the phone read-only).
- Live MR, ticket and PR status plus the Approve button (V2, `glab`, `jira`, `gh`).
- Slack thread activity (V3).
- A web UI (possible later, read-only on the SQLite file).

## Architecture

One repository, three products sharing one library:

| Unit | Kind | Responsibility |
|---|---|---|
| `TicklerCore` | Swift library (SwiftPM) | Model, SQLite store (GRDB), migrations, link extraction, date parsing (fr, en), notification and calendar planners (pure functions), session resumer, Apple Reminders import |
| `tickler` | CLI executable (SwiftPM, swift-argument-parser) | Claude's interface: add, list, show, done, snooze, edit, rm, resume, import-apple. JSON output with `--json` |
| `Tickler.app` | SwiftUI app (Xcode project generated by XcodeGen) | Menu bar extra, main window, settings, notification scheduling and actions, EventKit sync, `tickler://` URL scheme |

The SQLite file is the single source of truth: `~/Library/Application Support/Tickler/tickler.sqlite`, WAL mode. The CLI writes directly to it, so it works while the app is closed. After every write the CLI posts the Darwin notification `io.github.pixibixi.tickler.changed`; the app observes it, reloads and reconciles notifications and calendar events. The app also reloads every minute (relative times) and on wake.

Rejected: an app-as-server with a thin CLI client (no writes while the app is down), and keeping Apple Reminders as the store behind a custom UI (duplicate notifications, metadata stuck in notes).

## Data model

### `reminder`

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | 6 chars, lower-case base32 without ambiguous letters, typed in the CLI |
| `title` | TEXT NOT NULL | |
| `notes` | TEXT NOT NULL DEFAULT '' | Plain text, multi-line |
| `dueAt` | DATETIME NOT NULL | Stored UTC, shown local |
| `originalDueAt` | DATETIME NOT NULL | First due date, to show "rescheduled N times" |
| `rescheduleCount` | INTEGER NOT NULL DEFAULT 0 | |
| `status` | TEXT NOT NULL | `open`, `done`, `deleted` (soft delete) |
| `sessionId` | TEXT NULL | Claude Code session UUID |
| `cwd` | TEXT NULL | Folder of that session |
| `source` | TEXT NOT NULL | `claude` or `human` |
| `externalRef` | TEXT NULL | Apple Reminders id for imported rows |
| `notifiedAt`, `doneAt` | DATETIME NULL | |
| `createdAt`, `updatedAt` | DATETIME NOT NULL | |

### `link`

`reminderId` (FK, cascade), `position`, `url`, `kind` (`gitlabMR`, `jira`, `grafana`, `slack`, `githubPR`, `other`), `label`. Rebuilt from the notes plus explicit `--link` values on every write. Kind and label come from the URL shape (`/-/merge_requests/221` gives `repo !221`, `/browse/OPS-2204` gives `OPS-2204`, `/archives/` on a slack.com host gives `Slack thread`).

### `calendarEvent`

`reminderId` (PK, FK), `eventIdentifier`, `calendarId`, `syncedHash`. Written by the app only.

Migrations run through `DatabaseMigrator`, both from the CLI and the app, so either can create the file.

## CLI

```
tickler add <title> --at "YYYY-MM-DD HH:MM" [--notes <text> | --notes -] [--link <url>]... [--session <uuid>] [--cwd <dir>] [--json]
tickler list [--due today|week|overdue|all] [--project <name>] [--status open|done] [--json]
tickler show <id> [--json]
tickler done <id>
tickler snooze <id> (--for 15m|1h|2d | --to "YYYY-MM-DD HH:MM")
tickler edit <id> [--title <t>] [--at <date>] [--notes <text>|-]
tickler rm <id>
tickler resume <id>
tickler import-apple [--list Claude]
```

- `--session` and `--cwd` default to `CLAUDE_CODE_SESSION_ID` and the current directory, which is what the skill relies on.
- `--at` on the CLI only takes the strict format: Claude resolves relative dates before calling.
- `--due today` includes overdue ones (the daily check wants both).
- Exit codes: 0 ok, 1 runtime error, 2 usage error, 3 not found.
- Messages and JSON keys are English only.

## Date parsing (app)

`DateGrammar` protocol, one implementation per language (`fr`, `en`), tried active language first then the others. ISO `YYYY-MM-DD HH:MM` is always accepted. Covered forms: `demain 9h30`, `lundi 10h`, `dans 2h`, `dans 30 min`, `15:00`, `jeudi 14h`, `tomorrow 9:30am`, `monday 10am`, `in 2h`, `3pm`. A bare time already past today means tomorrow. A weekday means the next such day (today's weekday means next week). Anything in the past is rejected.

## App

### Menu bar

`MenuBarExtra` with the window style. Icon: the template glyph plus a count of overdue and today reminders; the glyph turns red while one is overdue. Popover: the "Next" card with Resume, Snooze, Done; grouped list (Overdue, Today, Tomorrow, Later collapsed); hover actions per row; footer with "Open window ⌘O" and the calendar sync state.

### Window

`NavigationSplitView`:

- Sidebar: views Today, Next 7 days, Overdue, All, Done; Projects derived from the last path component of `cwd`; sync state at the bottom.
- List: 7-day strip that filters on a day, search on title and notes, groups by due bucket.
- Detail: relative due chip, title, folder, actions (Resume ⌘R, Snooze menu, Done ⌘↩, Open ticket), notes with clickable links, links list, session state (running in WezTerm or ended), calendar event line. Title, date and notes edit in place; the date field takes free text through the date parser.
- Quick add ⌘N: title, free-text date with a live preview of the parsed date, notes. Source `human`, no session.

The app has no Dock icon unless the window is open (activation policy switches between accessory and regular). Launch at login through `SMAppService.mainApp`.

### Settings

Calendar (writable calendars or None), WezTerm binary path (default resolved: `/opt/homebrew/bin/wezterm`, then `/Applications/WezTerm.app/Contents/MacOS/wezterm`), language (System, English, French; UI change needs a relaunch), launch at login.

### Session resume (built in)

`SessionResumer` in the core replaces `claude-resume.sh`:

1. Read `~/.claude/sessions/*.json` (`sessionId`, `pid`, `cwd`), check the pid is alive with `kill(pid, 0)`.
2. Otherwise scan processes (`proc_listallpids` plus `KERN_PROCARGS2`) for `claude --resume <id>`.
3. Alive: find the pane whose `tty_name` matches the process tty (`wezterm cli list --format json`), `wezterm cli activate-pane`, bring WezTerm to front.
4. Not alive: `wezterm cli spawn --cwd <dir> -- env -u CLAUDECODE ... zsh -lic "claude --resume <id>"` (or `wezterm start` when no mux is running), then activate.

A `TerminalDriver` protocol isolates WezTerm. The CLI `resume` additionally closes the pane it was launched from when that pane is not itself a Claude session, like the script did. Failures surface as an error toast in the app and a message on stderr in the CLI.

## Notifications

- Authorization: alert, sound, badge. When the user's style is Banner, a hint in the window points to System Settings (the app cannot pick the Alert style itself).
- Actions: Resume (foreground), Snooze 15 min, Snooze 1 hour, Tomorrow 09:30, Reschedule… (text input parsed by the date parser; unparsable or past input opens the window on the date field with the text prefilled), Open ticket (first Jira link), Open Slack thread (first Slack link), Open link (first other link, only when no Slack link), Done. Clicking the body opens the window on the reminder.
- Categories are static, so all 6 link combinations (ticket yes or no, times Slack, other, none) are registered at start, with localized titles.
- Scheduling by reconciliation: a pure `NotificationPlanner` takes open reminders and pending requests and returns what to add and remove. Wanted set: open reminders due in the future, nearest first, capped at 64 (macOS pending limit). Request identifier: `<id>@<dueAt epoch>`, so a snooze replaces the request.
- Catch-up at start and on wake: overdue open reminders with no `notifiedAt`; 1 to 3 get one notification each, more get a single summary. `notifiedAt` is set on delivery (`willPresent`) or on catch-up.
- Done removes the delivered notification and the calendar event. Snooze and reschedule bump `dueAt` and `rescheduleCount`, then both planners run.

## Calendar sync (EventKit)

- Full access to events (write-only cannot fetch an event back by id).
- Event: reminder title, start `dueAt`, 15 min, availability free, no alarms, URL `tickler://open/<id>`, notes = reminder notes plus the links.
- Pure `CalendarPlanner`: for open reminders due from 7 days ago to 60 days ahead, create a missing mapping, update when the content hash changed, delete events of done or deleted reminders and of reminders that left the window. An event the user deleted or moved by hand is left alone until the reminder itself changes.
- Changing calendar deletes the events in the old one and recreates them.
- Failures (access denied, calendar gone) show in red in the sidebar footer; the rest keeps working.
- Owner prerequisite: create the "Claude" calendar in Google Calendar and set its default notifications to none.

## Internationalization

String Catalog with English (development language) and French. System language by default, overridable in Settings through the `AppleLanguages` user default of the app. CLI is English only.

## Import from Apple Reminders

`tickler import-apple --list Claude`: one-shot, reads open reminders of the list through EventKit, parses the note footer (`Session Claude : <uuid>`, `Reprendre : ... <uuid> '<dir>'`) into `sessionId` and `cwd`, strips it from the notes, stores the Apple id in `externalRef`, skips rows already imported. Apple Reminders is left untouched.

## Claude Code skill

The `reminders` skill (dotfiles) is rewritten on `tickler` on a branch, merged only after the owner validates the app. `claude-reminders.sh` and `claude-resume.sh` go away. Rules kept: 30 min minimum between two reminders, no relative offset in a title, follow-ups after an MR or a rollout, calendar import. Rescheduling becomes `tickler edit --at` instead of add plus delete.

## Tooling

- SwiftPM package (`Package.swift`) for `TicklerCore`, `tickler` and the tests; `project.yml` (XcodeGen) for the app, the `.xcodeproj` is not committed.
- `make build`, `make test`, `make lint`, `make app`, `make install` (app to `~/Applications`, CLI to `~/.local/bin`). `DEVELOPMENT_TEAM` optional; ad-hoc signing otherwise.
- SwiftLint and SwiftFormat, lefthook pre-commit (format check, lint, gitleaks), markdownlint.
- GitHub Actions on macOS runners: build and test, lint, app build, actionlint, markdownlint, CodeQL (Swift), dependency review, PR title check, scorecard. Actions pinned by digest.
- Renovate: SwiftPM, GitHub Actions and regex-pinned tools, same cooldown and automerge policy as the owner's other repos.

## Testing

TDD on the logic that decides product behavior, in the core:

- Date grammars (table-driven, frozen now): wrong parses mean reminders at the wrong time.
- Link extraction and classification: drives which actions appear.
- Notification and calendar planners: the reconciliation is where duplicates or lost reminders would come from.
- Store: CRUD, soft delete, reschedule counters, filters (today includes overdue).
- Import footer parsing.
- Session resumer decisions with a fake session registry, fake process table and fake `wezterm cli list` output.

Not unit-tested: SwiftUI views, EventKit and UserNotifications adapters (thin, verified by the manual checklist in the plan). CLI covered by a few end-to-end tests on a temporary database.
